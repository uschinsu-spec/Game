# Vạn Tiên Lục v1.0 — Stability and Completion Roadmap

## Release intent

This document defines a safe completion plan for the existing Phaser 3 + TypeScript portrait RPG. Work is staged so the current playable loop and local saves are not destabilized by large feature additions.

## Confirmed current foundations

- Phaser 3 / TypeScript / Vite client with a portrait-first 2.5D perspective scene.
- Automated combat, four regular skills and one ultimate.
- Normal, elite and boss enemies; boss HP phase thresholds and guaranteed crafting-core drop are documented in v0.9.
- Cultivation has 9 major realms × 4 stages in the current realm table.
- Inventory, equipment slots, consumables, crafting, daily welfare and kill quests.
- Local browser persistence with a 12-hour AFK cap.

## Changes in this branch

### AFK reward consistency

- Align the active `SaveSystem.grantOfflineRewards` rate with the published gameplay systems specification: 5 character EXP per full offline minute, 4 silver per minute and 1 spirit stone per 8 full minutes.
- Clamp elapsed time inside the reward grant method to a finite range of 0–12 hours, so direct callers cannot bypass the cap with invalid or oversized values.
- Clarify the reward toast as character EXP. The active implementation calls `player.addExp`, not `player.addCultivationExp`.
- Keep existing save keys and snapshot shape unchanged to preserve existing player saves.

### Important runtime note

`WorldScene.create()` currently loads and binds `SaveSystem`, then grants the elapsed offline rewards. The older `OfflineProgression` service is not wired into the active scene path; do not bind both services during future refactors, or offline time may be claimed twice.

## Completion roadmap

### P0 — Reliability and player data
- Preserve backward compatibility for v2/v3 save snapshots and legacy timestamp migration.
- Add automated tests for save migration, malformed storage, offline time clamping, level-100 reward behavior and repeated visibility changes.
- Add a visible local-save status / export-import backup flow.
- Document that localStorage is device/browser-local and is not cloud-backed or tamper-proof.

### P1 — Progression and economy
- Build a deterministic progression simulator using actual monster reward curves, level EXP formula, realm gates, quest rewards, daily rewards and AFK rewards.
- Tune time-to-level and time-to-breakthrough targets from measured simulations; do not change realm costs or save schema without a migration.
- Separate character EXP from cultivation EXP in every label, reward, quest and tooltip.
- Add economy sinks only after silver/spirit generation per hour has been measured.

### P1 — Combat and content
- Add unique boss attack patterns (telegraphs, area attacks, adds and recovery windows), rather than only increasing stats between HP phases.
- Add a repeatable dungeon loop with explicit difficulty, entry cost, reward table and first-clear reward.
- Add skill upgrade data and tests for cooldown, MP cost, target count and damage scaling.

### P2 — Equipment and long-term progression
- Add item affixes, upgrade tiers and set bonuses behind versioned item data.
- Add crafting recipes with transparent input/output and deterministic validation.
- Keep drop tables data-driven and test expected value per hour to avoid runaway inflation.

### P2 — UX, performance and release
- Add battle recap (damage dealt/taken, kill count, boss time).
- Add accessibility controls for reduced flashes, readable text and sound toggles.
- Profile low-end mobile devices; pool transient effects and avoid unnecessary per-frame allocations.
- Run portrait viewport, resize, background/foreground, save migration and long-session QA before release.

## Acceptance criteria

A release candidate is not complete until:
1. `npm run build` succeeds with no TypeScript errors.
2. Existing v2/v3 saves load without losing equipment, inventory, realm or claims.
3. AFK rewards are granted once, are capped at 12 hours and match the published rate.
4. Character EXP and cultivation EXP are clearly distinguished in UI feedback.
5. Combat, boss drops, inventory/equipment and daily claims pass the manual QA checklist.
6. Mobile portrait and desktop resize smoke tests pass.

## Explicit non-goals until backend work exists

Cloud accounts, server-authoritative progression, multiplayer, cross-server ranking, real-money payments and social/sect services must not be represented as live features without a backend, security model and operational plan.
